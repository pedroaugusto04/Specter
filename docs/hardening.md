# Security and reliability changes

These changes take effect through the usual build/deployment. No manual changes to
GitHub variables, secrets, database schema, or existing environment files are required.
JWT authentication, refresh and logout remain stateless and retain their existing behavior.

## Behavior changes

- URL validation rejects private IPv4 addresses written as hexadecimal, dotted or expanded
  IPv4-mapped IPv6, as well as expanded IPv6 loopback/unspecified addresses. Public mapped
  addresses remain supported.
- Codex configuration tasks always use `read-only`. The previous `CODEX_SANDBOX` setting is
  no longer consumed, including values still present in existing environment files or
  GitHub variables. The CLI writes its final response via `--output-last-message`.
- Compiler subprocesses receive a runtime/provider authentication allowlist instead of
  the backend's entire environment. Database, Redis, JWT, encryption, notification and
  storage credentials are not forwarded. Provider login files remain in their existing
  locations. Custom CLI wrappers cannot rely on arbitrary backend environment variables.
- The HTTP scraper stops reading and cancels responses above 10 MiB, including bodies
  without a trustworthy Content-Length. The limit applies to decoded bytes. Such a
  response fails rather than being accepted as truncated extraction evidence. This
  budget is specific to HTTP scraping, not a total Chromium process memory limit.
- URL probes remain available anonymously. They are limited to 10 requests per minute
  per authenticated user or anonymous IP as observed by Fastify. The limiter is local
  to each API process. Anonymous visitors behind the same proxy/IP share a bucket;
  forwarded client headers are not newly trusted. Excess requests receive HTTP 429.
- A session lookup returning HTTP 401 means unauthenticated. Network errors and backend
  failures propagate as errors, preserving previously cached user data. The dashboard
  includes session lookup failures in its connection error state, and the landing page
  offers a retry when session verification fails.
- Contract-only changes now trigger deployment of both consumers. Extension-only changes
  trigger frontend packaging/deployment. PR checks include frontend typechecking/build
  and backend typechecking/lint in addition to the existing tests and evaluations.

Optional tuning (`HTTP_MAX_RESPONSE_BYTES`, `RATE_LIMIT_PROBE_MAX`) is validated at startup
and mirrored in the examples, Compose files and deployment generator. The defaults above
are applied when no overrides exist.

## Dependency compatibility

Next.js remains on major version 15. Drizzle ORM/Kit and Zod were updated, with Zod's
native JSON Schema exporter replacing `zod-to-json-schema`. Discriminated unions now
use the equivalent `oneOf` representation; model results still pass the domain schema.
Validation errors retain the existing HTTP envelope and explicit required-field messages;
default messages and validation details generated by Zod can differ between versions.
PostCSS uses an npm override to the project's patched PostCSS dependency, keeping the
Next.js major upgrade separate. Lockfiles are included for reproducible installation.

## Remaining boundaries

DNS preflight validation is not connection-level DNS pinning. Complete DNS-rebinding
protection remains outside this change. The CLI sandbox and environment allowlist do
not establish a separate container or deny all reads of files accessible to its OS user.
Container identity, Chromium sandbox flags and provider credential locations are unchanged.
The actual authenticated Codex/AGY service and production deployment need operational
verification; automated tests use portable subprocess doubles without model calls.
